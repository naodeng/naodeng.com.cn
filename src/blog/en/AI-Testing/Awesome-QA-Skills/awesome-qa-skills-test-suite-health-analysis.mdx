A test suite can be large, green, and unhealthy. Flaky reruns, quarantined checks, duplicate intent, slow tails, and unclear ownership all reduce the trust of the signal.

The Test Suite Health Analysis Skill reviews suite health from CI history, duration distributions, reruns, quarantine lists, duplicate tests, maintenance records, and defect evidence. It produces TSH-## governance candidates, not execution results.

Health is a set of observable conditions, not a single green percentage.

## Test Suite Health Analysis Skill: what it is for

Use this Skill to understand whether a suite is trustworthy and maintainable enough for its intended feedback role. It does not execute tests, infer coverage from counts, or accept risk for a Human.

A good TSH finding includes subject, preconditions, concern, source evidence, validation, impact, priority, owner, close condition, and evidence state.

Use it when a suite is slow or flaky, quarantine keeps growing, duplicate tests are suspected, or CI health needs an evidence-based review.

## Begin with project facts

| Material | What to provide | What to do when it is missing |
| --- | --- | --- |
| Run history | Duration distribution, retries, failures, environment, and versions | Keep missing windows visible |
| Suite inventory | Tests, ownership, quarantine, tags, and duplicate intent | Do not count files as coverage |
| Maintenance and defects | Repair records, changed areas, escapes, and failure clusters | Separate correlation from cause |
| Decision boundary | Feedback role, owner, stop condition, and next validation | Do not approve release |

Use a request like this:

~~~text
Use the test-suite-health-analysis Skill.\n\nTask: Assess the checkout pre-merge suite after three weeks of rising reruns and a growing quarantine list.\nInputs: [CI history, duration data, quarantine records, test inventory, owners, defect links]\nScope: [pre-merge checkout suite]\nConstraints: [do not execute tests or call candidate count coverage]\n\nProduce TSH-## findings with source, evidence state, impact, owner, close condition, and smallest validation action.
~~~

## Make the result usable by the next person

| Output field | Why it exists | Example status |
| --- | --- | --- |
| Health finding | Flakiness, duration, duplication, isolation, or maintenance concern | TSH ID and evidence |
| Impact | How the issue affects trust or feedback | Priority and boundary |
| Validation action | Smallest check before changing the suite | Owner and method |
| Residual state | What remains unassessed or NOT_RUN | No coverage claim |

Every conclusion should point to a source, evidence state, and next action. If evidence is missing, use pending, blocked, unassessed, or NOT_SCORED instead of filling the gap with confidence.

## Focused example: Separate flaky reruns from real product failures

Reruns increased after a browser upgrade, while product defects stayed stable and most failures cluster in one fixture. The Skill should identify an environment or isolation hypothesis, keep product-risk inference separate, and request a controlled replay. It should not delete the tests or call the suite healthy from one green rerun.

The analysis describes supplied suite-health evidence. It cannot prove execution coverage, root cause, or release readiness.

## Improve the first result with better baseline input

Provide a fixed time window, run IDs, duration and retry data, quarantine history, suite and owner inventory, defect links, environment changes, and the feedback role the suite serves.

A useful handoff includes input versions, scope, time window, evidence index, assumptions, Human decision boundary, and the smallest validation action.

## Common traps

1. Using test count or green percentage as overall health.
2. Treating quarantine as deletion without recording the protected risk.
3. Calling a cluster a root cause without environment or reproduction evidence.

## Two practical questions

### Should quarantine always be removed?

No. First record why it was quarantined, what risk it protects, who owns it, and what closes or escalates the quarantine.

### Does a healthy suite mean full coverage?

No. Health concerns signal trust and maintainability; coverage is a separate traceable question.

The Skill is most useful when attached to one real project artifact and kept with its source evidence. Start narrow, validate the uncertain part, and expand only when evidence supports it.
