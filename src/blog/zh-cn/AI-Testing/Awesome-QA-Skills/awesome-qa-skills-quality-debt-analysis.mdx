质量债务是持续带来成本或风险的质量缺口。分析时要找到问题来源、说明已观察到的影响，并比较偿还、隔离和限期接受风险的方案。记录时间长，不足以把问题认定为债务；优先级也不能只看年龄。

## 区分债务与相邻问题

判断持续成本前，先分清记录属于哪一类。产品缺陷、不稳定的测试资产、临时例外和证据缺口需要不同处理。

| 记录类型 | 要记录什么 | 判断边界 |
| --- | --- | --- |
| 当前产品缺陷 | 已观察到的行为、受影响用户、来源与现有控制 | 单独追踪缺陷本身，不要改名为测试债务 |
| 测试或架构债务 | 资产、来源、持续投入或暴露、年龄和依赖 | 说明缺口持续带来成本的证据 |
| 临时例外 | 已授权范围、负责人、原因、控制和到期日 | 接受风险需要授权并安排复核日期 |
| 证据缺口 | 评估债务所缺少或已过期的数据 | 结论保留未评估，不能把缺失当作证据 |

工单、旧测试或未完成事项本身都不足以证明存在债务。源 Skill 要求记录债务项、来源、影响、年龄、优先级、负责人和偿还权衡。

## 衡量持续影响

用观察到的维护投入、风险暴露或检测延迟，说明缺口如何持续累积影响。例如，重跑和排查会占用工时，但要估算货币金额就需要有来源的费率。缺少频率或成本数据时，应提供定性或条件范围，并说明还需要什么证据。

排序时要同时考虑业务影响、风险暴露、可探测性、依赖和偿还投入/收益。年龄只是一个信号；新出现但暴露严重的问题，优先级可能高于存在已久、影响较小的事项。

## 在确定优先级前审计证据

排序前先检查证据的完整性、可信度、时效性和可比性，再记录 known、missing、conflicting、stale、out_of_scope 和 assumptions。核对证据是否覆盖可比较的时间段、相关构建和对应资产。

- known / 已知：引用支持结论的问题单、运行记录、事故、工时记录或现有控制。
- missing / 缺失：请求最小所需的日志、时间范围、影响来源或责任人信息。
- conflicting / 冲突：若来源对原因或影响说法不一，先并列记录，待负责人裁定。
- stale / 过期：保留旧历史，但不能把它说成当前频率或控制状态。
- out_of_scope / 范围外：指出本轮排除的产品缺陷或发布决策。
- assumptions / 假设：写出维持临时排序所需的验证方法。

分开呈现事实、证据支持的推断、候选建议和 Human 决策。波动套件与逃逸缺陷同时出现，不足以证明前者造成后者。

## 示例：按持续风险排序，不按年龄排序

源 Skill 附有一组脱敏合成样例。下面的事项和判定仅用于演示，不是真实项目记录或业务批准。

| 事项 | 提供的证据 | 样例判定 |
| --- | --- | --- |
| Q-1 | 重复的测试 helper 已存在 180 天，每月维护 1 小时，没有高风险保护缺口 | `LOWER_PRIORITY`；年龄本身不代表影响更大 |
| Q-2 | 新的退款测试只有 1 天，完全 mock 被测对象，昨天漏检重复扣账，资损风险仍然存在 | `HIGHER_PRIORITY`；较新的事项有更高的已述暴露，但样例没有证明 mock 是漏检根因 |
| Q-3 | 已确认的生产重复扣账缺陷尚未修复 | `PRODUCT_DEFECT`；按当前产品缺陷追踪，不要归成测试债务 |
| Q-4 | helper 重构工单已关闭，但没有行为回归或维护影响证据 | `NOT_CLOSED`；仅关单不能证明债务影响已消失 |
| Q-5 | 有重构代码、独立回归、维护样本和负责人验收记录 | `CLOSED`；样例提供了关闭所需的证据 |

### QDA-01 候选发现：评估退款测试缺口

| 发现字段 | 示例记录 |
| --- | --- |
| 对象与来源 | Q-2，即脱敏样例中完全 mock 被测对象的退款测试；没有提供真实测试编号或仓库历史 |
| 触发条件与关注点 | 样例记录测试使用 mock，同时漏检了昨日发生的重复扣账且资损风险仍在。需要核对测试边界，但不能据此认定 mock 导致漏检。 |
| 证据状态 | 合成样例中的信息为 `known`；真实测试历史、缺陷关联和生产影响范围仍为 `UNASSESSED` |
| 影响、优先级和负责人 | 按样例判为相较 Q-1 更高优先级。真实负责人和影响分级规则未提供；项目排序前先找到测试负责人。 |
| 验证与停止条件 | 在约定窗口内核对测试定义、运行历史和重复扣账证据。若确认存在生产缺陷，暂停债务排序，转入产品缺陷或事故处理流程。 |
| 关闭条件 | 修改相关资产，独立检查预期行为，证明持续暴露或检测缺口已消失，并记录负责人验收。 |

此例把测试缺口和当前产品缺陷分开。若接受剩余风险，要记录获授权的负责人和到期或复核日期。

## 选择偿还、隔离或接受

逐项比较最小偿还动作与隔离、监控或限时接受方案。记录依赖、负责人、目标日期、剩余风险，以及用什么证据确认影响发生变化。

| 选项 | 适用情况 | 记录与退出条件 |
| --- | --- | --- |
| 偿还 | 持续成本或风险值得投入修复 | 指明要修改的资产、独立行为检查、效果变化证据和验收负责人 |
| 隔离 | 近期无法偿还，但可以限制暴露或降低影响 | 记录隔离范围、补偿控制、监控信号、负责人和复核日期；控制失效时触发升级 |
| 接受 | 获授权负责人决定在限定范围内暂时承担剩余风险 | 写明理由、范围、补偿控制、剩余风险、批准人和到期或复核日期；续期需要重新批准 |

工单关闭或补齐文档，不代表债务已经偿还。按 Skill 的关闭规则，还要修改相关资产、独立检查预期行为、证明持续影响已消失，并由负责人验收。条件未满足时，保持未关闭；若暂时接受风险，则记录获批的例外和复核期限。

## 把债务处置放进质量循环

![质量债务处置循环：记录并排序有来源的债务，选择偿还、隔离或限期接受，按所选方案执行必要变更与验证，并继续跟踪未解决风险](/images/blog/ai-testing-quality-loops/quality-debt-analysis-quality-loop-zh.svg)

AI 生成的测试可以提示遗漏的场景，但生成本身不会偿还债务。先复核、去重候选用例，再关联需求并执行；之后还要独立确认原有债务影响是否改变。逃逸缺陷、维护投入、检测延迟和未解决的证据缺口都应带入下一轮复核。

## 准备可复核的记录

提供债务编号、来源证据、影响和现有控制、年龄、可比较的观察周期、投入或风险暴露数据、依赖关系和偿还选项。标明每个金额或频率是观测值、估算还是未知数。除非关系有来源支持，否则把当前产品缺陷和发布决策留在债务记录之外。若要输出 CSV、JSON 或工单，先约定 schema、枚举值、必填字段和证据来源。

## 常见错误

1. 把所有旧测试都叫债务。
2. 只看年龄，忽略暴露、可探测性和偿还成本。
3. 根据相关性直接指定根因。
4. 关闭工单，却没有证据证明债务影响已消失。

## 最佳实践

- 排序前先区分当前产品缺陷、测试或架构债务、临时例外和证据缺口。
- 用可观察的维护投入、风险暴露或检测延迟估计持续成本。没有可靠费率时，保留定性或有条件的估计。
- 按影响、暴露、可探测性、依赖和偿还成本/收益排序，年龄只是一个信号。
- 只有相关资产已修改、独立检查通过、持续影响已消失并完成负责人验收后，才能关闭债务。

## 新手入门：先评估一项债务

1. 选一个测试、架构资产或例外，找到它的来源和当前控制。
2. 提供可比较的观察周期、影响或投入证据、年龄、依赖和可选偿还动作。
3. 请 Skill 先分类、标出已知和缺失信息，再给出最小验证步骤。缺少影响证据或负责人时，优先级先保持未评分。

## 常见问题

### 可以接受质量债务吗？

可以，但要由获授权的负责人记录影响、控制、剩余风险和到期或复核日期。

### 怎样证明债务已偿还？

沿用原来的证据指标，说明相关资产已修改、预期行为经过独立验证，而且债务影响已经消失。

### AI 生成的测试能用来关闭债务项吗？

不能直接关闭。生成用例要先经过复核和运行；关闭仍需要修改相关资产、独立行为检查、债务影响消失的证据和负责人验收。
