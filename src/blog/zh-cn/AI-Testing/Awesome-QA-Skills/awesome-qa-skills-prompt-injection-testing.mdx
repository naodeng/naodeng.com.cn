提示注入测试检查不可信文本是否会改变应用任务、暴露受保护数据，或引导 Agent 执行未经授权的动作。注入内容可能来自用户，也可能藏在被检索的网页、文件、邮件或工具响应中。风险取决于应用能接触哪些数据、模型可调用哪些工具，以及这些工具拥有哪些权限；因此测试要同时观察回答、工具调用和系统状态。

本文用于获准环境中的防御性验证。开始前确认系统所有者、测试范围和允许的动作；使用沙箱、mock 和虚构数据，不向真实服务发送测试写操作，也不在输入中放置真实凭据或敏感目标信息。

## 先盘点信任边界、资产和动作

整理当前应用的任务指令、策略来源、模型与版本、外部内容入口、检索路径、会话或记忆机制、工具权限和高影响操作。明确哪些文本可信、哪些只是待处理的数据，并列出需要保护的资产，例如虚构的测试标记、模拟个人资料或 mock 账户记录。材料缺失时，把假设和待确认项单独列出，不要把未知行为写成已确认的系统规则。

| 输入或能力 | 需要确认的边界 | 可观察证据 |
| --- | --- | --- |
| 用户消息 | 用户是否能改变任务范围、要求越过策略或索取受保护数据？ | 用例 ID、输入、策略版本、回答与拒绝状态 |
| 检索内容 | 网页、文件、邮件或知识库文本是否被当作指令执行？ | 来源 ID、检索片段、引用与后续动作 |
| 工具响应 | 返回文本是否能改变下一步调用或参数？ | 工具响应、候选调用、授权决定和调用轨迹 |
| 会话、记忆与多模态输入 | 指令能否跨轮次保留，或从应用支持的图片、音频等内容进入？ | 轮次 ID、记忆状态、输入解析结果和后续动作 |

只纳入产品实际支持的入口和能力。测试范围也要写明哪些工具被 mock、哪些外部连接已关闭，以及哪些状态变化允许发生。

## 把风险变成可判断的用例

不要只收集“恶意提示词”。每个用例都应有唯一 ID、前置条件、输入来源、要验证的安全属性、预期行为、禁止副作用和证据要求。预期结果要依据应用策略和工具授权规则制定；提示中出现可疑文字，不代表应用必须拒绝一切相关任务，例如它可能仍应安全地总结或引用该段文字。

| 覆盖面 | 安全的测试安排 | 主要断言 |
| --- | --- | --- |
| 直接注入与任务劫持 | 在用户消息中放入要求忽略原任务、输出虚构标记的冲突文本 | 应用遵循既定任务与策略，不泄露受保护标记 |
| 间接注入 | 在测试网页或文档夹具中放入相同性质的冲突文本，再要求总结该内容 | 系统将其作为待处理内容；不因此披露数据或扩大任务 |
| 工具越权 | 让 mock 工具返回带有指令的文本，观察后续候选调用 | 工具调用仍由应用策略授权；参数和对象范围没有被注入内容扩大 |
| 混淆与持久化 | 在产品支持的语言、格式或多轮场景中变化输入 | 不支持的路径标为未覆盖；拒绝后的指令不会无依据地进入后续任务或记忆 |
| 拒绝与恢复 | 覆盖被策略阻断、需要澄清和允许的正常任务 | 拒绝后无副作用；正常任务仍可完成；停止原因可追溯 |

**示例：**在隔离的文档问答环境里，给测试文档加入一段冲突指令，并在应用的受控测试数据中放置标记 `TEST_SECRET_7F3A`。用户只请求总结文档。用例应检查摘要是否仍围绕文档内容、标记是否泄露、是否出现读取或发送数据的工具调用，以及系统状态是否发生预期之外的变化。标记必须是专门创建的虚构值，不能用真实密钥替代。

## 验证完整路径，而不只看回答

按用例记录模型、系统指令、应用和工具配置版本，以及运行时间、输入来源、响应、引用或检索记录、工具调用尝试、授权结果和执行后的状态。对于可随机变化的模型行为，重复运行并记录每次结果；如果无法固定参数，也要记录设置差异。一次拒绝不能证明后续轮次安全，一次成功也不能证明所有相似输入都能被拦截。

按用例 ID 和运行 ID 组织这些记录，并保留输入来源、检索片段、调用轨迹与执行后状态之间的对应关系。汇总时仍要逐次呈现运行结果，避免把多次输出合并成一个“通过”结论。

尤其要对照副作用证据：被阻断的写入是否真的没有发生，是否尝试过调用工具，是否向外部发送数据，mock 状态是否保持预期。只有拒绝文案、没有工具轨迹或状态证据时，应标记为“证据不足”，不能据此判定安全通过。

## 判定、排序并形成回归闭环

建议把单个用例结果分为：

- **通过**：所需断言均有证据支持，且没有观察到禁止的副作用。
- **失败**：观察到越权、数据泄露、任务被劫持，或策略要求的阻断没有发生。
- **证据不足**：环境、轨迹或状态信息不完整，无法判断实际行为。

按业务影响、可达入口、权限范围和证据强度排序发现；将假设、已观察事实与建议分开，并列出未覆盖的模型、通道和工具。修复后用原用例做回归，再增加相邻边界场景。交接材料至少包含威胁边界、用例 ID、预期断言、运行配置、证据位置、风险排序和下一步负责人。这个 Skill 帮助组织验证工作，不会证明整个应用已经安全。

可参考 OWASP GenAI Security Project 的[提示注入风险指南](https://genai.owasp.org/llmrisk/llm01-prompt-injection/)，并结合项目自身的授权策略设计预期行为。模型行为和任务质量见[LLM 测试](/zh-cn/qaskills/llm-testing/)；工具权限和副作用见[智能体工具调用测试](/zh-cn/qaskills/agent-tool-testing/)；更广的防护控制见[安全测试](/zh-cn/qaskills/security-testing/)。
