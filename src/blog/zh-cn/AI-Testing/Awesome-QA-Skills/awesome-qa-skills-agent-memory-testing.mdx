智能体记忆测试关注助手如何跨用户和会话存储、检索、更新与遗忘信息。复核时要把每条记忆追溯到来源和适用策略；只看最终回答，无法确认实际取回了哪个版本。

## 保留可追溯的记忆记录

对每条已有记忆保留租户与用户范围、memory ID、内容版本、来源、写入时间、有效期，以及同意、撤回或删除状态。把检索出的条目及其来源信息关联到回答，便于复核者查看相同证据。

## 跨范围与时间对照检索

依据项目给定的一致性窗口和偏好优先级规则，比较同一查询在两个租户中可见的记忆集合，并保留获授权检索作为对照。检查更新后是否仍返回旧内容、到期条目是否继续出现，以及撤回或删除后的检索是否符合已有策略。

不要默认最后写入的偏好优先，也不要自行编造保留时长。若优先级、有效期、删除传播范围或预期一致性窗口缺少来源，应将相应判断保留为待确认。

## 用一条记录走完更新与删除复核

以下是隔离环境中的说明性场景，预期结果仍须以项目策略为依据。可以用两个虚构的偏好值观察同一记忆从写入到删除的轨迹：

| 阶段 | 检查动作 | 留存证据 |
| --- | --- | --- |
| 写入 | 在获准的测试租户写入一条记忆 | 租户与用户范围、memory ID、来源、版本、写入时间、同意状态、有效期策略 |
| 更新 | 把测试偏好从 A 改为 B，并在策略规定的一致性窗口内重新查询 | 更新事件、返回的 memory ID 与版本、检索结果和来源信息 |
| 删除 | 发起获准的删除请求，检查策略列出的索引、缓存和其他存储范围 | 删除请求 ID、各存储范围的检查记录、完成状态和时间 |

如果更新后仍取回 A，要对照策略规定的传播窗口和版本规则判断；不能因为一次查询为空，就断言所有存储都已删除。备份或传播策略缺失时，应把结论限定在已检查的范围。没有检索轨迹、删除范围或授权信息时，标记为“证据不足”或“待确认”；这份计划不能替代真实执行证明。

## 沿实际存储范围追踪删除

先依据系统架构和策略列出实际使用的索引、缓存与备份，再把删除请求对应到各自的传播规则和保留期限。未说明的存储范围应列为待确认。

## 区分记忆生命周期与访问权限

记忆测试追踪长期保存状态，包括来源、时效、租户隔离、保留与遗忘。智能体权限测试: https://inaodeng.com/zh-cn/qaskills/agent-permission-testing/；判断某个主体能否执行具体读取或工具动作。两者可能相关，但不能用其中一个结论替代另一个。

## 记录 AMT-## 发现

记录对象或规则、来源、触发条件或适用范围、预期关注点、证据状态、影响与优先级、责任角色、关闭条件和验证方法。确认的事实、推断、候选检查与 Human 决策应分开。

## 将验证保持在隔离范围内

把已有策略、记忆记录、检索轨迹和删除证据作为静态材料复核。如需进一步验证，提出最小且获授权的检查，使用脱敏数据、mock 或隔离环境。没有相应证据时，不要声称测试已执行或删除已完成。

## 安装与调用

安装这个 Skill：

```bash
npx skills add https://github.com/naodeng/awesome-qa-skills/tree/main/skills/zh --skill agent-memory-testing
```

调用 agent-memory-testing 时，提供记忆策略、租户范围、条目版本、来源、有效期或删除规则，以及现有检索证据。可以从一条脱敏记录开始：

```text
请按 agent-memory-testing 复核这条脱敏记忆记录。只依据我提供的策略和证据，检查租户/用户范围、版本与来源、有效期、同意状态及删除传播范围。分别列出已确认事实、待确认项和证据不足项；不要推断未提供的保留期限或删除结果，也不要访问真实账户或秘密数据。
```

## 常见问题

**一次检索没有返回记录，能证明记忆已经删除吗？** 不能。它只说明本次查询在当前检索路径下没有返回结果。还要根据实际架构检查策略列出的索引、缓存和其他存储，并保留各范围的删除证据。

**调用 Skill 后会自动检查线上账户吗？** 本文的复核流程基于提供的材料；如需运行验证，应先确认授权和隔离环境，并使用脱敏数据或 mock。
