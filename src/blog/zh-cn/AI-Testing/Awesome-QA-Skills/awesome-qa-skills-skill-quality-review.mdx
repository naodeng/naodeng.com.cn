审一份 Skill，不能只看说明写得顺不顺。它的主文件、Prompt、metadata、示例、引用资源和评测用例可能各自正确，却组合不起来；单独复制安装后，也可能缺少实际需要的文件。

skill-quality-review 用于检查整个 Skill 包的工程完整性，并把静态结论与尚未获得的运行证据分开。它不替用户改 Skill，也不把目录齐全或校验命令通过说成模型行为有效。

## 从目标和边界开始

先确定要审查的 Skill、语言、目录和审查目标。若目标路径或材料缺失，应先列出缺口，不能凭另一份相似 Skill 推断。

然后检查这些方面：

- **职责与范围**：这个 Skill 解决什么问题，哪些任务明确交给其他能力。
- **触发和输入**：描述是否能引导正确使用，关键材料缺失时怎么处理。
- **输出契约**：要求的字段、状态、证据和格式是否明确。
- **资源关系**：Prompt、示例、references 和脚本路径是否真实存在，加载方式是否清楚。
- **独立安装**：只复制这个目录时，相对资源仍可访问，且没有依赖另一个 Skill 的私有文件。
- **双语与评测准备度**：语言版本是否表达同一契约，eval 案例是否覆盖关键边界。

## 静态检查能证明什么

文件检查可以证明路径存在、字段和引用一致、文档覆盖了某些规则；它不能证明模型会稳定触发 Skill、运行时工具可用，或业务用户认可输出。

报告应把阻塞问题、重要建议、信息缺口和证据边界分开。比如，路径引用失效是可直接确认的问题；“模型总会遵守这项规则”则需要特定运行证据，不能靠读文件得出。

## 让 AI 帮忙逐项核对

把整个 Skill 目录及审查目标提供给 AI，让它列出具体文件依据。审查者要回到原文件确认引用、版本和路径，尤其检查它是否把未执行的行为判断写成结论。

~~~text
请使用 skill-quality-review 审查以下 Skill 包。

Skill 目录与语言：[路径、语言]
审查目标：[范围或变更]
可用材料：[SKILL.md、Prompt、metadata、示例、references、evals]

检查职责边界、触发、输入输出契约、相对资源、独立安装、
双语一致性和评测准备度。每条发现请引用具体文件与依据。
将阻塞问题、建议、信息缺口和证据边界分开。
这是静态审查：不要声称运行时行为、模型效果、业务验收或发布批准已通过。
~~~

审查结束时，应能回答：哪些问题可以仅凭文件确认，哪些还要安装或运行后检查，哪些需要产品或业务负责人判断。结果不应以总分掩盖阻塞项。

### 它和 Skill 评测有什么区别？

质量审查检查包结构、职责、路径和证据边界；skill-evaluation 设计和解释行为评测。前者可以指出评测用例缺失，但不会代替实际运行评测。

### 安装成功能说明 Skill 质量合格吗？

不能。安装检查只说明相应安装步骤完成；它不能证明触发、输出或模型行为满足目标。

### 可以让 Skill 质量审查自动修改文件吗？

这个 Skill 的定位是只读审查。可以把建议交给维护者，是否修改以及如何验证由维护流程决定。
