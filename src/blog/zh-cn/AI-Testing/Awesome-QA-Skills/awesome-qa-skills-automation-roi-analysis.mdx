自动化投资回报分析要在同一时间窗、同一成本口径下，比较一个明确的自动化候选与人工方案。有效判断应覆盖建设、执行、复核和随变化产生的维护；只计算省下多少执行分钟，无法说明投资能否回本。

## 为什么需要这个 Skill

每季度运行一次的流程，可能不值得建设脆弱的端到端套件；稳定的计算校验却可能只需少量自动化就能提供价值。结论取决于已提供的执行频率、风险、投入、维护和收益证据，而不是笼统地偏好自动化。

## 先确定候选项和成本边界

先说明打算自动化什么：计算不变量、数据准备、完整用户流程，还是报表对比。还要与简化流程、抽样、保留专家复核或延后投资等方案比较。

| 成本或收益 | 分开记录 | 需要的证据 |
| --- | --- | --- |
| 建设 | 一次性的设计、实现、夹具和上手成本 | 工时估算或已记录投入 |
| 运行 | 机器占用时间和人工复核 | 执行次数、时长、复核投入及计量单位 |
| 维护 | 随变化产生的修复、数据维护、诊断和负责人投入 | 变更记录和实际维护工时 |
| 人工方案 | 准备、执行、复核和返工 | 工时记录或有来源的受限估算 |
| 收益 | 风险降低、反馈速度或减少决策延迟 | 缺陷历史、风险暴露或决策证据 |

人工工时、机器占用时间和货币不能直接相加。只有项目提供换算费率时才转换；没有货币口径时，单独报告人工工时和机器时间。

## 统一时间窗后再计算

计算前固定候选项、时间窗和单位。源 Prompt 对一个时间窗定义了以下关系：

```text
净节省 = 执行次数 ×（人工单次成本 − 自动化单次成本）
         − 维护成本 − 建设成本
```

所有项都必须采用同一单位和时间窗。若要报告 ROI 比率，必须写清分子和分母；Skill 没有规定一个适用于所有项目的财务定义。若只有工时数据、没有货币换算，就报告工时节省，不要虚构货币回报。

如果每个周期的持续净节省大于零，回本窗口数为建设成本除以每周期持续净节省，并向上取整为完整周期。如果持续净节省小于或等于零，则应说明在这些假设下没有回本点。

接着根据项目提供的低、基准和高情景，分别调整执行频率及变更导致的维护成本，并标出结论或收益正负何时变化。缺少费率和工时数据时，只能给公式和条件范围，不能给伪精确回报或自动采纳结论。

## 排序前审计证据

源 Prompt 要求记录 known、missing、conflicting、stale、out_of_scope 和 assumptions。做 ROI 时，数据能否比较与数据是否完整同样重要。

| 状态 | 自动化决策中的例子 | 处理方式 |
| --- | --- | --- |
| known / 已知 | 有版本的发布日历及人工投入记录 | 标注时间段和来源 |
| missing / 缺失 | 建设投入、人工复核时间或产品变化后的维护量 | 保留为缺项，不能按零计算 |
| conflicting / 冲突 | 一份估算包含专家复核，另一份没有 | 并列口径并先统一单位 |
| stale / 过期 | 执行频率来自已废弃的发布节奏 | 未确认前不外推到新时间窗 |
| out_of_scope / 范围外 | 本轮排除生产自动化或业务风险接受 | 保留明确边界 |
| assumptions / 假设 | 初版暂用负责人认可的执行频率范围 | 写明验证方法和依赖此假设的结论 |

把已确认事实、证据支持的推断、候选建议和 Human 决策分开。自动化与缺陷减少同时发生，并不能证明前者造成了后者。

## 示例：每季度运行的专业报表

假设有一个示例请求，要评估一个每季度运行、经常变化且需要专业数据的税务报表流程。此处只给出场景描述，没有建设估算、运行记录、失败率、复核投入、维护历史或财务换算依据。

合理的初步分析应比较边界明确的候选，例如只自动验证稳定的计算规则，还是自动化整个报表流程，而不是马上决定采纳哪一种。比较前需要统一时间范围、人工和自动化单次投入、专家复核、建设工作、变更维护，以及有来源的换算费率。资料不足时，结果保持未评分。

### ARO-01 候选发现：估算漏掉了维护成本

| 发现字段 | 示例记录 |
| --- | --- |
| 对象与适用范围 | 税务报表自动化候选；仅当负责人正在比较自动化、人工或抽样方案时适用 |
| 触发条件 | 决策估算没有时间窗，或没有计入变更产生的维护 |
| 预期关注点 | 若遗漏专家复核、故障诊断或流程变化后的修复，可能高估节省 |
| 来源与证据状态 | 示例只提供频率和变化背景，没有成本或执行证据；标记 **UNASSESSED / NOT_SCORED** |
| 影响、优先级和负责人 | 业务影响与证据充分前不定优先级；由自动化负责人和财务或流程负责人共同评审 |
| 验证与关闭条件 | 以有来源的同单位成本计算同一时间窗，并使用项目提供的低/基准/高频率和维护情景。另一位评审者能复算，且 Human 已从备选方案中作出决定后，才关闭分析。 |

这是评审候选，不是已经计算出的 ROI，也不是自动化指令。Skill 可以准备比较，但不会执行流程或批准投资。

## 把分析转成决策

输出应说明候选、备选方案、来源输入、时间范围、成本、收益、敏感性、证据缺口和剩余风险。结论可以是自动化、简化、抽样、保留人工或延后；还要写清哪些条件变化会推翻建议，并指定负责人和复核触发点。

## 怎样准备更好的输入

提供稳定的候选定义、发布或业务频率、可比较的观察周期、人工和机器投入、复核及维护记录、收益证据和项目认可的换算费率。对敏感数据做脱敏，并说明数字是观测、估计还是假设。

## 常见错误

1. 只把节省的执行时间当成全部收益。
2. 把缺失的维护或复核成本按零计算。
3. 在没有来源换算的情况下混合工时、机器时间和货币。
4. 不写时间窗和敏感性，只给一个点估算。

## 常见问题

### 一定要有精确的财务数字吗？

不需要。使用有来源的范围并明确假设。无法换算成货币时，分别报告工时并说明还缺什么。

### 风险降低无法直接量化怎么办？

可以用缺陷历史、风险暴露或决策延迟作为有边界的代理指标，说明来源，并保留因果关系尚未证实这一点。
