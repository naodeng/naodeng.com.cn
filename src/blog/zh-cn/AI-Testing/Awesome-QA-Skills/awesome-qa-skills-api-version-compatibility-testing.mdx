API 升级不只是增加一个 `/v2`。它会改变客户端对字段、错误、排序、默认值和不可逆迁移时点的假设。

API 版本兼容性测试用于把新旧契约放到真实消费者行为中比较，并识别安全发布、迁移和回滚边界。

当团队需要围绕“字段演进、错误兼容、默认值、弃用、混合版本流量、迁移和回滚”工作时，使用 API 版本兼容性测试 Skill。它把模糊的测试请求变成有来源、有假设、有输出字段和下一步动作的受限分析。

[Awesome QA Skills](https://github.com/naodeng/awesome-qa-skills) 按语言和测试阶段组织 Skill。[系列总览](https://inaodeng.com/zh-cn/blog/ai-testing/introduction_of_awesome_qa_skills/) 解释通用安装方式，本文只聚焦 API 版本兼容性测试。

## API 版本兼容性测试 Skill 用来做什么

好的兼容性测试会包含混合版本流量。旧客户端和新服务端需要共存一段时间，才能暴露干净 v2 环境会掩盖的默认值和失败路径。

它适合这些场景：团队需要重复检查字段演进、错误兼容、默认值、弃用、混合版本流量、迁移和回滚；多个证据来源互相矛盾；交接时必须说明哪些内容仍未验证。

完整执行契约位于 [API 版本兼容性测试 提示词](https://github.com/naodeng/awesome-qa-skills/tree/main/skills/zh/testing-types/api-version-compatibility-testing/prompts/api-version-compatibility-testing.md)。调用 Skill 前先阅读它；提示词定义了详细流程和输出契约。[源目录](https://github.com/naodeng/awesome-qa-skills/tree/main/skills/zh/testing-types/api-version-compatibility-testing) 中包含入口文件以及实际存在的配套资料。

## 用一份项目材料开始

| 材料 | 这次提供什么 | 缺失时怎么处理 |
| --- | --- | --- |
| 版本契约 | 新旧 Schema、示例、错误、默认值和弃用日期 | 未文档化行为标为假设 |
| 消费者清单 | 移动端版本、Web、Worker、合作方和发布状态 | 包含升级速度慢的客户端 |
| 迁移控制 | Feature flag、双读、回退、遥测和回滚方案 | 数据不兼容时，回滚方案并不完整 |

可以这样调用：

```text
请使用 api-version-compatibility-testing Skill。

任务：把移动端结算客户端从 v1 订单响应迁移到包含嵌套价格和新可空字段的 v2
输入材料：[需求、版本、链接、日志、报告或数据路径]
范围：[本次包含和排除的对象]
未知项：[缺失的环境、账号、数据或权限]
期望输出：[按风险排序的发现、证据状态和下一步动作]

先审计输入。分开写事实、假设和待确认问题。没有运行记录时不要声称已经执行。
```

## API 版本兼容性测试 要交付什么

| 输出字段 | 它要回答什么 | 示例状态 |
| --- | --- | --- |
| 兼容性发现 | 破坏性、有条件兼容或安全改动 | 消费者与版本 |
| 迁移步骤 | 双读、适配器、Feature flag 或客户端发布 | 前置条件与证据 |
| 回滚边界 | 哪些可以逆转，哪些数据已经改变 | 决策负责人 |

没有运行记录、查询结果或原始产物时，不要写“已通过”。好的兼容性测试会包含混合版本流量。旧客户端和新服务端需要共存一段时间，才能暴露干净 v2 环境会掩盖的默认值和失败路径。

## 在项目里跑一轮

先从一个边界清楚的小回合开始：把移动端结算客户端从 v1 订单响应迁移到包含嵌套价格和新可空字段的 v2。在迁移开关下同时运行 v1、v2 移动端，并让 Worker 继续读取旧的扁平价格字段。验证金额、null 处理、错误恢复、遥测和部分客户端发布后的回滚。

交接产物要保留输入版本、时间窗口、证据索引、负责人和下一次验证动作。Skill 可以整理不确定性，不能制造缺失的产物。

## 如何把初版做得更好

如果第一次调用只有一行目标，输出就应该保持受限。补充来源版本、受影响对象、环境、已知缺陷和决策负责人，才能从看起来完整的清单推进到可用评审。

这里补充信息会改变结果，因为字段演进、错误兼容、默认值、弃用、混合版本流量、迁移和回滚必须接回证据，不能只靠熟悉的测试套路推断。

## 容易踩的坑

1. 只比较 Schema，不比较消费者假设。
2. 遥测还没证明旧字段无人使用就删除它。
3. 写入已经只使用新表示后，仍把回滚称为安全。

## 常见问题

### 新增可选字段一定兼容吗？

不一定。消费者可能拒绝未知字段，或误解 null 和默认值行为。

### 什么时候应该停止迁移？

当破坏性发现没有负责人、证据或可逆发布步骤时。
