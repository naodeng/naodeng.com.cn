质量仪表盘应先说明谁会使用、要做什么决策，再让每项信号都能追溯到证据。质量仪表盘设计 Skill 会检查受众、决策问题，以及每个面板实际支持的结论。

## 什么时候使用

当团队要设计或复核仪表盘的受众、决策问题、面板、下钻路径、数据新鲜度或告警边界时，可以使用这个 Skill。它能分析已提供的方案、结果和指标，并把缺口整理成验证工作；不会编造指标数值、阈值、根因或发布批准。

## 复核流程

对每类受众写清楚决策问题和时间窗口。每个指标都要说明定义、来源、分子与分母、刷新时间和限制，然后写明数据变化时查看者应采取什么动作。

| 仪表盘元素 | 要明确的契约 |
| --- | --- |
| 受众与决策 | 谁会采取行动，面板会支持什么选择？ |
| 指标 | 定义、单位、分子、分母、来源和统计人群 |
| 新鲜度 | 最近刷新时间、延迟、抽样及过期数据的显示方式 |
| 下钻 | 指向运行、义务、缺陷或事故证据的链接 |
| 告警边界 | 触发条件、负责人、动作，以及升级或停止条件 |

缺失值必须如实呈现。零、null、NOT_RUN、BLOCKED 和过期数据含义不同；不能把零或上一次的绿色结果代替不可用证据。总体比例也不能掩盖小规模高风险人群或 P0 阻塞项。

## 检查面板能否正确表达状态

把仪表盘方案转成几条可复核的显示场景。先用设计检查确认规则写清楚；若要证明真实界面和数据管道按规则运行，还需要相应环境与执行记录。

| 场景 | 面板应如何处理 | 需要检查的依据 |
| --- | --- | --- |
| 分母缺失或为零 | 显示不可计算或无数据状态，不默认为 0% | 分母定义、空值规则和统计窗口 |
| 来源超过新鲜度要求 | 显示最后更新时间和过期状态，不沿用旧的绿色结论 | 刷新时间、延迟规则、过期阈值的负责人 |
| 总体正常但某个高风险群体异常 | 保留该分组和影响范围，摘要不得把它平均掉 | 分组定义、样本量限制和告警规则 |
| 下钻链接失效 | 将证据追溯标为缺失，并定位责任数据源 | 面板到运行、缺陷或事故记录的关联键 |
| 告警触发 | 明确接手人、处置动作、升级路径和解除条件 | 告警契约与值班或业务责任安排 |

还要确认总览、分组和下钻页面对同一指标使用相同的定义、时间窗口和筛选范围。数值相同也可能来自不同口径，需核对实际规则。

## 示例：按项目规则呈现仪表盘状态

源 Skill 附有一组脱敏合成样例。样例项目规定：未关闭的 P0 会阻断发布，数据超过 24 小时标为过期，未运行的测试标为 `NOT_RUN`。这些规则只适用于样例，不是所有团队都应采用的门禁。

| 样例 | 提供的证据 | 仪表盘状态 |
| --- | --- | --- |
| D-1 | 100 项中通过 99 项，另有 1 项 P0 未关闭 | `BLOCKED`；总体通过率不能掩盖阻塞项 |
| D-2 | 显示绿色的数据来自 48 小时前 | `STALE`；标出最后刷新时间，不沿用旧的绿灯结论 |
| D-3 | 面板显示失败数为零和绿色，但测试没有运行 | `NOT_RUN`；没有运行记录就没有测试结果 |
| D-4 | 当前 100/100 证据、无 P0、可下钻到 run17，且定义和时间窗口完整 | 按样例规则标为 `PASS` |

源样例的预期判定依次为 D-1 `BLOCKED`、D-2 `STALE`、D-3 `NOT_RUN`、D-4 `PASS`。这些状态用于检查仪表盘是否按既定项目规则映射证据，不代表生产批准或通用发布策略。

## 交付哪些内容

遇到尚不能支持决策的面板或规则时，用 QDD-## 记录发现，包括对象、来源、触发条件、预期问题、证据状态、影响与优先级、负责人角色、关闭条件和验证方法。验证场景还要写明前提、刺激、预期行为、所需证据和停止条件。建议和已执行的测试必须分开。

## 结论边界

这个 Skill 可以复核决策视图，不能代替遥测设计或发布门禁，也不会查询生产系统或批准风险例外。输入不完整时，结论只适用于已提供的设计材料，不能说明当前产品质量。

## 最佳实践

- 先确定受众和决策，再选能支持该决策的指标与面板。
- 让复核者能找到指标定义、统计人群、分子与分母、来源版本、刷新时间和过期规则。
- 总览中保留 P0 阻塞项和小规模高风险群体。每条告警都要有负责人、动作、升级路径和解除条件。
- 依赖线上仪表盘前，先用样例证据检查各类显示状态。向工具输出发现时，先约定 schema、枚举值、必填字段和证据链接。

## 新手入门：先做一个决策视图

1. 选一个受众和一项决策，例如日常测试分诊或发布准备度。
2. 选一个面板，提供指标定义、数据源、统计人群、时间窗口、刷新规则和下钻链接。
3. 请 Skill 检查面板如何呈现正常数值、分母为零、证据缺失、数据过期和阻塞项。扩展视图前，先确认行动负责人。

## 让仪表盘进入质量循环

![仪表盘决策循环：明确决策，展示新鲜证据及状态，调查问题，更新测试并在重跑后刷新视图](/images/blog/ai-testing-quality-loops/quality-dashboard-design-quality-loop-zh.svg)

日常测试中，AI 生成的用例要先经过人工复核和验收，才能进入测试结果视图。没有执行记录时，仪表盘应显示候选状态或 `NOT_RUN`；执行后再把结果关联到需求和构建。阻塞、过期来源或失败运行会触发调查、修复和重跑，负责人根据新证据决定后续动作。

## 常见问题

### 质量仪表盘能替团队批准发布吗？

不能。它可以呈现决策证据，但发布策略和风险接受必须由负责人员决定。

### 缺失或过期的数据应该怎样显示？

明确显示状态和最后更新时间。不能用 0 或之前的绿色结果替代不可用或过期的证据。

### AI 生成的测试用例能直接在仪表盘上显示为通过吗？

不能。经过复核、验收和实际运行前，只能显示为候选项或 `NOT_RUN`。执行后要把结果关联到对应需求和构建，方便复核证据。
