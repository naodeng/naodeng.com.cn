# Diffuse Glass Theme Design

## 目标

将 naodeng.com.cn 的全站视觉方向调整为“克制弥散玻璃”。玻璃承担空间层级和品牌识别，柔和色雾负责画布氛围；页面不再使用 ASCII 字符、字符纹理、终端模拟或代码图形作为视觉元素。

主题覆盖 Header、首页、Footer、Blog、Wiki、AI Wiki、Docs、Guild、Prompts、Workflows 与 QA Skills，同时保持中英文、桌面端和移动端结构一致。

## 设计原则

1. **玻璃是主视觉**：透明度、模糊、细亮边和柔和阴影构成统一语言。
2. **内容优先**：长文正文使用低透明度或接近实色的弱玻璃，不能以视觉效果牺牲对比度。
3. **弥散而不喧闹**：画布仅使用少量低饱和色雾，不使用字符、网格、图片纹理或持续漂移动画。
4. **层级明确**：不同组件使用强、中、弱三级玻璃，不把所有内容做成相同卡片。
5. **双主题一致**：Light 与 Dark 使用相同结构和层级，只调整画布、色雾、文字、边框、透明度与阴影。

## 视觉系统

### 画布

- Light：暖白底色，叠加淡蓝紫与极浅青色的大面积弥散色雾。
- Dark：深蓝黑底色，叠加低亮度蓝紫色雾。
- 色雾固定在页面底层，不能遮挡点击、引发横向滚动或随滚动产生明显抖动。
- 不使用 ASCII、点阵网格、照片、3D 芯片或商务插画。

### 玻璃层级

#### Strong Glass

用于 Header、搜索弹窗、移动导航与重要浮层。

- 较高模糊和适度饱和度。
- 清晰的细亮边与稳定阴影。
- 背景不透明度足以保证导航文字和控件对比度。

#### Medium Glass

用于 Hero、首页重点卡片、Footer、内容侧栏和目录容器。

- 中等模糊和透明度。
- 允许底层色雾轻微透出。
- 重点区域可以有柔和高光，但不使用紫色发光描边。

#### Weak Glass

用于 Blog、Wiki、Docs 等正文容器和普通信息卡片。

- 接近实色，模糊较低。
- 优先满足长文阅读、代码块、表格和引用区的对比度。
- 避免多层玻璃连续叠加。

### 边框、阴影与圆角

- 边框统一为低对比 hairline；深色主题使用浅色透明边，浅色主题使用冷灰透明边。
- 阴影大而柔和，表达悬浮层级，不使用强烈彩色 glow。
- 延续现有圆角层级；浮层和重点容器使用较大圆角，正文内部元素保持更克制的圆角。

### 字体与图标

- Hero 标题保留衬线显示字体，正文沿用现有双语字体体系。
- 卡片恢复并保留 Material Icons 语义图标。
- 删除所有为 ASCII 视觉引入的等宽元信息、字符图形和组件命名。

## 组件应用

### Header

- 使用 Strong Glass，保持现有导航、语言切换、搜索和 Light/Dark 按钮。
- 首次访问仍跟随系统主题；用户点击后固定为 Light 或 Dark。
- 不增加额外装饰带或扩大导航高度。

### Hero

- 重命名并重构现有 ASCII Hero 组件为玻璃 Hero。
- 保留标题、说明和两个 CTA。
- 使用 Medium Glass，依靠底层色雾与玻璃透光形成视觉焦点，不添加字符背景。

### 首页区块

- 任务卡、能力卡、探索卡与文章卡使用 Medium 或 Weak Glass。
- 保留现有 Material Icons、编号、文案和链接行为。
- 通过透明度和层级区分重点，不批量添加伪标签或装饰字符。

### 内容页面

- Blog、Wiki、AI Wiki、Docs、Guild、Prompts、Workflows 和 QA Skills 的全局布局继承画布与主题 token。
- 正文、侧栏、目录、搜索与列表容器按 Weak/Medium Glass 分级。
- 代码块、表格和引用区域保持独立实色或高不透明度，避免背景穿透影响阅读。

### Footer

- 使用 Medium Glass，保留全部链接、社交入口、语言切换和版权信息。
- 不添加背景字符、图形地形或额外动画。

## 主题 Token

全局提供语义 token：

- `canvas`
- `surface`
- `text-primary`
- `text-secondary`
- `glass-strong`
- `glass-medium`
- `glass-weak`
- `glass-solid`
- `glass-border`
- `glass-highlight`
- `shadow-glass-sm`
- `shadow-glass-md`
- `shadow-glass-lg`
- `mist-primary`
- `mist-secondary`
- `focus`

删除 `ascii`、`ascii-muted` 及所有只服务于字符视觉的变量和测试。

## 动效与性能

- 色雾不持续动画。
- 交互只保留短距离 hover 抬升、边框变化和主题切换过渡。
- 遵循 `prefers-reduced-motion`。
- 移动端降低模糊半径和阴影强度，避免过度 GPU 合成。
- 提供无 `backdrop-filter` 时的高不透明度实色回退。

## 无障碍

- Light 与 Dark 中正文、导航、按钮和链接保持可读对比度。
- 主题按钮可键盘访问，标签描述切换后的目标主题。
- 玻璃透明度不能让背景色雾干扰文字识别。
- 焦点样式在两种主题下均清晰可见。

## 实施范围

1. 清理 ASCII 变量、组件命名、测试和旧文档契约。
2. 建立三级玻璃与双色雾 token。
3. 重构全局画布、Header、Hero 和 Footer。
4. 将首页卡片与内容页面布局接入对应玻璃层级。
5. 验证中英文、Light/Dark、桌面/移动、键盘操作和降级行为。

不新增 UI 框架、图片资源、运行时视觉依赖或持续动画。

## 验证标准

- 源码与设计文档中不再存在主题相关的 ASCII 实现或契约。
- `npm run build` 通过。
- `npm test` 通过。
- 首页与主要内容路由 E2E 通过。
- Light/Dark 切换、刷新持久化和首次系统偏好行为正常。
- 桌面与移动端无横向溢出、玻璃遮挡、不可见文字或异常层叠。
- 不支持 `backdrop-filter` 时仍可阅读和操作。
- `git diff --check` 通过，并保留用户原有未提交改动。

## 非目标

- 不重写现有信息架构、文案、路由或内容数据。
- 不统一重做所有组件 DOM。
- 不添加图片、视频、WebGL、Canvas 或重型动画。
- 不把所有元素做成相同透明度和圆角的玻璃卡片。
