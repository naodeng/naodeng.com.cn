# dsh-qa 双语项目官网设计

## 目标

在本站为 dsh-qa 建立面向访客的独立产品页，清楚说明它是面向 DeepSeek Harness 的本地 QA 工作台，并引导访客了解、安装和继续探索相关质量工程资源。页面以中文和英文分别呈现，不将站内项目列表替代为产品官网。

## 路由与语言

- 使用一个 Astro 动态路由，产出 `/zh-cn/dsh-qa/` 与 `/en/dsh-qa/`。
- 按当前站点的 `LOCALES`、`Astro.currentLocale`、`Base.astro` 与语言切换机制实现，不新增第二套 i18n 框架。
- 每个语言版本拥有对应的标题、描述、canonical URL、面包屑和互相切换的页面链接。

## 信息架构

1. **首屏**：深色“质量指挥中心”视觉。展示产品名、定位、local-first / DSH plugin / zero production dependency 标签，以及 GitHub、DSH 插件安装和独立运行三个行动入口。
2. **能力地图**：以简洁卡片说明项目与迭代、AI 协作、本地材料与质量任务四个能力域；避免声称 AI 自动结论可以取代人工质量负责人。
3. **质量交付流程**：用可访问的 HTML/CSS 流程展示“需求与范围 → 可评审计划 → 受控执行 → 可验证证据 → 交付门禁”。`PASS` 可进入交付，`WARN / BLOCK` 需评审；受控例外仅适用于可豁免的 WARN，不能将 BLOCK 变为通过。
4. **安装与运行**：并列说明 DSH 插件模式与独立模式，保留命令块、Node.js 前置条件及“插件变动后重启 DSH Web UI”的事实。明确独立模式不提供 DSH 原生会话、模型、技能和命令。
5. **适用场景与生态**：帮助访客判断何时使用 dsh-qa，并链接 GitHub、本站 QA Skills、QA Prompts 与相关 dsh-qa 博客文章。
6. **版本变更**：页面最底部的 Release notes 区域，按版本倒序；所有条目默认折叠。折叠标题保留版本、发布日期、简短摘要；展开后显示完整本站维护的中英变更项和官方 GitHub Release 链接。

## 视觉与交互

- 不改变全站的主题系统；页面自身用深色表面、细网格、青绿/蓝色状态色与等宽数字营造“质量指挥中心”感。
- 流程和状态不只依赖颜色：状态文字、图标或形状也必须可辨识。
- 动效仅用于悬停、焦点与低幅度背景层，遵守 `prefers-reduced-motion`。
- 移动端采用单列；安装命令允许横向滚动而不截断；按钮与折叠控件具有明显焦点状态和足够点击面积。
- Release notes 使用原生 `details/summary` 或同等语义化控件，默认关闭，并保留键盘操作与屏幕阅读器语义。

## 数据与事实边界

- 产品文案、能力清单、安装命令和版本变更存入一个本地、类型化的双语数据模块，由页面在构建时渲染；访客访问时不请求 GitHub API。版本的 ID、发布日期与 Release URL 使用一份共享事实记录，只有摘要和变更项按语言分别维护，避免双语版本事实漂移。
- 初始版本条目以 GitHub Releases 为准，至少包含 `v0.3.1`（2026-09-11）、`v0.3.0`（2026-09-11）和 `v0.2.0`（2026-09-01）；后续版本发布时在同一数据模块新增条目并保留对应 Release URL。
- 页面不得把源码审查、AI 建议、测试运行或发布标签描述成等价的质量结论。所有质量门禁都须维持“已验证证据 + 人工评审”的语义边界。

## 实现边界

- 新增页面路由和仅服务该页面的数据模块；仅在必要时新增小型页面私有组件。
- 将现有项目列表中 dsh-qa 的链接改为站内详情页，并在详情页提供 GitHub 外链，避免失去源码入口。所有 `PROJECTS_LIST` 消费者必须通过共享的站内/站外项目链接助手生成语言路径，不能只修复项目列表而遗漏资源页。
- 不修改部署配置、现有博客正文或 dsh-qa 仓库。

## 验收与验证

- `npm run build` 产出两个页面，且无类型、路由或 SEO 构建错误。
- 对双语地址进行本地浏览器检查：三个主行动入口、四项能力、五阶段流程、两种安装方式、生态链接、语言切换、全部 Release notes 默认折叠及任一条展开、桌面与移动布局均正常。
- 运行 `npm run seo:check`，并确认 canonical、标题与描述与路由一致。
- 检查 `git diff --check` 与最终 Git 状态，确保未混入无关改动。
