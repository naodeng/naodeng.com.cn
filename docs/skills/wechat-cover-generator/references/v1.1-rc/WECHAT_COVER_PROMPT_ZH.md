# 软件测试同学｜微信公众号封面通用提示词 V1.1-RC

复制本文件全部内容，填写末尾文章标题；在支持图片参考的工具中附上已确认的角色图与官方 Logo。此提示词独立可用，不依赖其他规则文件；但正式品牌验收依赖实际参考资产与工具能力。

## 任务
为软件测试、AI 测试及质量工程技术文章设计两张独立横版封面。默认输出 2.35:1（1880×800 px）及 16:9（1920×1080 px）。用户明确指定单一比例时只输出该比例。不得拉伸或机械裁剪另一版本；工具不能原生输出时，采用保留主体的画布扩展、独立布局及等比缩放，并核验实际文件尺寸。无法适配则注明限制。

## 品牌与角色
以原创专业技术杂志编辑插画为定位：成熟、亲切、温暖、理性、克制。暖奶油纸张 #F7F1E7，深墨绿标题 #344D43，雾蓝 #91B6CC，鼠尾草绿 #8FA593，石板灰 #646E75，琥珀黄 #D4B477。背景约60%为奶油色，实际按画面调整。细腻低对比纸纹，标题区更干净；主体有自然彩铅排线、颜色叠加、纸纹透出；核心轮廓清晰，内部结构细腻，纹理线轻柔；漫射光、柔和局部阴影。不是颗粒滤镜覆盖的矢量插画。

固定一位约35岁男性 QA 工程师，以用户提供照片衍生并经确认的角色图为基准：深色短发、深色眼镜、轻度卡通化但成熟自然的脸部和身体比例、亲和沉稳；默认鼠尾草绿卫衣，可用浅灰或蓝灰卫衣，搭配简洁马甲或外套。允许正面、侧面、四分之三视角及自然表情、动作；不改变身份特征。固定一个雾蓝色圆润小助手，头顶小弯角、简单深色五官、轻腮红、蓝色围巾、黄色对勾徽章、短小手脚、柔和填色，完整身高约为人物20–35%，按景别合理调整。人负责专业判断与责任，助手承担信息整理、提醒、验证辅助。参考图锁定身份而非复制姿势。缺少确认参考图时只能作为探索草稿。

## 标题
原标题优先。仅调整分行、字号、位置和不删减实质内容的主副标题拆分时无需确认。以等效中文字符估算：1–12完整展示；13–22自然分行；23–36优先主副标题；37以上若仍无法满足可读性，提出精简候选并等待明确确认，不得擅自使用。英文及数字可粗略按0.5单位估算，实际以渲染宽度与语义为准。保护 AI、QA、QE、Agent、Skill、RAG、LLM、E2E、API、TDD、CI/CD、产品名称、版本号、CVE编号、否定词、限定条件、疑问及因果关系；疑似错误单独提示而非擅改。用户明确给出封面标题时直接采用。

现代中文无衬线粗体，参考思源黑体/Noto Sans CJK SC 700–800，英文参考 Inter；自然中英文混排，不拆词，默认左对齐，主标题1–3行，行高1.15–1.35倍。1880×800主标题参考88–120px、副标题42–56px；1920×1080主标题96–136px、副标题48–64px。字面宽度及缩略图可读性优先，不强行缩小；最多两种主要字号字重层级。仅呈现已确认标题及必要副标题，默认无额外标语或标签。可用0–2处琥珀色彩铅下划线、雾蓝圈选或柔和色块。优先预留标题区并使用确定性文字排版；若工具只能一体生成，则必须核对实际文字。320px宽预览应自然阅读，180px宽应识别核心主题；375px为额外移动端检查，不代替前两项或真实客户端验证。

## 主题与构图
先识别文章领域（测试实践、测试工程化、AI Native QE、质量治理与专业发展）及表达类型（教程、原理、流程、比较、观点）；从标题/摘要/正文提取1个核心语义及0–2个辅助语义，不虚构未提供的事实。以1个核心视觉隐喻、1–3个辅助道具设计主题场景。参考映射：需求歧义→待确认卡片；覆盖缺口→缺失拼图；测试设计→分支路径；RAG→回答与来源连接；质量门禁→证据与待决策关卡；可观测性→信号与诊断路径；质量债务→累积负担与排序；韧性→弹性结构与恢复；TDD/质量循环→反馈环路；自动化→模块执行链；性能瓶颈→狭窄通道；安全补丁→修复结构及业务回归。映射仅为参考，不机械复用。根据主题让 QA 阅读、分析、评审、设计、比较、验证或判断；助手整理、提示、连接、检查或等待人工确认。

选择 T01 左文右图（默认/长标题/教程）、T02 左图右文（经验/工具）、T03 上文下图（短标题/科普）、T04 中心概念（原理/安全/架构）、T05 对比分析（观点/对比）、T06 流程叙事（工作流/自动化）。标题是第一视觉焦点，主题插画第二，角色是品牌识别。标题区域约30–55%，插画30–55%，独立留白15–20%，按场景分配而非像素硬限。左右边距4–6%，上下6–8%；核心标题、面部、助手、核心概念及Logo完整。人物可半身或全身，合理景别不是异常裁切。双比例保持标题、核心隐喻、角色身份及品牌风格相同，可独立调整布局。完整横版优先，不保证任意方形裁切。装饰默认D1低密度；深度技术D0–D1，科普D1–D2；不为填空而装饰。

## 官方 Logo
使用用户上传的蓝白金黄色圆形“软件测试同学”原始 Logo（书本、清单、对勾），保持原图色彩及结构，不重绘。生成阶段预留干净右下角，后期以原图或经确认透明版合成一次，不透明度100%，直径为封面高度10–14%，默认12%（96px/约130px）；默认距右5%宽、距底6%高。原图白色方形外背景若未获确认去除则保留原图，不冒充透明版。Logo区域与核心角色、围巾、道具不得相交；先预留干净区域，不足时以等比缩放及画布扩展腾出空间，或在10–14%范围缩小；必要时调整至其他底部安全位置；禁止生成虚线占位圆。无需重复文字水印。不具备资产或合成能力时输出待合成草稿并明确说明，不能声称已完成。

## 差异化与负向约束
每篇不同主题应有独立场景；有历史素材时对比最近5–10张和同系列最近10–20张，尽量在3个可变维度不同（至少1个为核心隐喻、场景、角色动作）；同系列可共享构图，同篇双比例不作跨文重复比较。固定角色、Logo、配色不计作重复。始终使用固定主参考图而非上一张生成图作为唯一参考；不自动更新品牌资产。无历史资料则注明未验证。

P0 全局强制：禁止标题错字乱码、未经确认改写、技术误导或虚构数据/架构/产品能力、角色身份漂移（T05可在两个对比场景中重复同一固定人物）、严重人体结构错误、Logo重绘变形重复、额外文字/Logo、核心元素遮挡或异常裁切、错误尺寸或损坏文件、仅换标题复用旧图、双比例核心内容不一致。
P1 风格：禁止写实摄影、3D、过度Q版、动漫、儿童绘本、光滑商业矢量、霓虹赛博朋克、荧光色、大面积纯黑白或蓝紫渐变、金属玻璃塑料感、强光重影、油画厚涂、水彩大面积晕染、做旧破损纸张、密集便签贴纸、无关科技符号、信息图式拥挤或主体过小。Logo原色例外。
P2 按主题加载：AI不暗示全面取代QA或生成即有效；Agent不暗示无限自主；RAG不暗示引用即正确；证据支持、待核查、不相关可用对勾、放大镜、叉号分别表达；安全拒答必须为独立决策路径，不得作为第四种证据状态或与三种状态并列分支；自动化/E2E不暗示覆盖全部活动；CI/CD/门禁不暗示通过即无条件发布；安全不虚构漏洞机制或攻击场景、不暗示补丁后绝对安全、不用恐慌式黑客视觉；指标/性能不虚构数据及百分比；架构不虚构真实组件流向与产品界面；测试不暗示无缺陷保证；观点不把疑问变结论或制造焦虑。适用P2技术误导按P0处理。冲突以强制准确性和完整性优先，再品牌基线、主题约束、布局偏好、创意；最新确认修订覆盖旧规则（男性、蓝色助手、原始Logo无重复水印）。

## 执行与验收
先检查输入及资产，形成简短设计简报（分类、主题、隐喻、角色动作、构图、负向规则）；常规自动执行，标题删改或品牌变更须人工确认。每次图片生成调用只允许一个文章、一个比例、一张独立画布；禁止拼图、总览图、尺寸标签和虚线占位符。分别生成两个画布，优先确定性合成标题和Logo。实际检查每张图片：文字、技术语义、双角色、人体结构、官方Logo、标题阅读、核心元素完整、无多余内容、实际尺寸与文件可打开、非旧图换标题。必须验证的项目缺证据即阻断正式验收。每张按标题20、品牌20、技术20、构图10、移动阅读10、彩铅10、配色5、差异化5评分；各项用100/80/60/40/0%等级，有证据才评分。历史缺失时可排除该可选维度，按已验证权重归一化并报告覆盖率。评分为启发式；每张≥85，单项≥60%，Critical/Major未解决数为0，所有必要门禁通过。双图检查标题、主题、隐喻、人物、助手、Logo、配色、媒介一致且各自构图合理，整组取较低评分，不用平均掩盖失败。95以上可提名参考样例但需确认。

Critical：文字/技术错误、身份漂移、Logo失真、严重裁切/人体错误、输出损坏或错误比例、旧图仅换标题；Major：明显画风、构图、阅读、主题关联缺陷；Minor：局部轻微色差或装饰不足。优先修正文字/Logo/尺寸，再局部编辑、重排、重设计或重生成。保留候选版本，修复后回归相关规则及双图一致性；整图重生成做完整回归。默认至多两轮自动整改（每轮可涉及两张图），仍失败则输出待整改候选和原因，不无限循环。无法执行的检查注明未验证，不编造分数或通过结论。

输出实际封面文件（若工具具备能力），简短报告每张实际尺寸、评分及覆盖率、门禁、缺陷、整改次数、双比例与历史检查状态。区分草稿、待整改、待人工确认、已批准；未获人工确认不得声称已批准/已发布。剩余Minor需人工接受；Critical/Major不豁免。
