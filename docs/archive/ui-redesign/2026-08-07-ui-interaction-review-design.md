# UI 与交互优化设计草案

日期：2026-08-07

## 背景

当前站点是 Astro 双语内容站，承载博客、Wiki、AI Wiki、Guild、提示词、工作流、QA Skills、项目和标签等内容。现有 UI 干净、响应式基础完整，搜索、阅读进度、目录、代码复制、语言切换和移动导航已经具备。

这次优化不做整体重设计，目标是降低信息过载、强化关键入口、提升搜索与移动端体验，并保持现有内容结构和双语路径稳定。

## 推荐方案

采用中等范围优化：先调整首页信息架构和搜索体验，再收紧移动导航、页脚和文章长文辅助交互。

不优先做大规模视觉重设计。原因是站点内容体系已经很完整，当前最大问题不是视觉风格不可用，而是信息层级太平均、重复卡片太多、关键路径不够突出。

## 优化范围

### 首页

首页首屏保留站点标题、简介和两个主要 CTA，但增强“这个站点能帮用户做什么”的定位表达。首屏下方增加三个主入口：

- 博客：阅读长期文章与经验总结
- Wiki / AI Wiki：查概念、术语和系统知识
- QA 工具内容：进入提示词、工作流和 QA Skills

首页后续区块从“全部内容同一种卡片铺开”调整为多种展示密度：

- 最新文章使用更紧凑的列表或精选列表
- 重点内容入口使用少量大卡片
- Wiki、AI Wiki、标签保留 chip cloud，但减少视觉噪音
- 项目和 Guild 放在较低位置，作为补充探索入口

### 全局导航

桌面端继续保留顶部导航和分组下拉，但减少主导航的认知压力。移动端导航改为更清楚的抽屉结构，优先展示搜索、博客、Wiki / AI Wiki、QA 工具、关于。

导航交互保留现有键盘、Escape 关闭、点击外部关闭能力，并检查下拉菜单和移动抽屉在窄屏下不会遮挡或溢出。

### 搜索

搜索弹窗升级为轻量 Command Palette：

- 搜索结果展示内容类型，例如 Blog、Wiki、AI Wiki、Prompt、Skill、Project
- 支持键盘上下选择结果，Enter 进入
- 空状态展示常用入口或最近内容
- 加载失败时显示明确但克制的提示

搜索仍使用现有本地索引，不引入远程搜索服务。

### 文章阅读

保留阅读进度、目录和代码复制。优化重点：

- 长文目录的当前章节高亮更稳定
- 移动端目录入口位置更靠近文章开头
- 文章末尾分享区减少无效或低价值入口，优先保留复制链接和主要社交平台
- 相关内容入口更清楚地区分“继续读”和“查词条”

### 页脚

页脚从一串链接改为分组结构：

- 内容：博客、Wiki、AI Wiki、Guild、提示词、QA Skills
- 站点：关于、归档、系列、标签、赞助、链接
- 法务与系统：版权、隐私、状态、RSS、站点地图

社交图标保留，但移动端缩小占位，避免页脚开头过重。

## 组件边界

主要改动应限制在以下组件和页面：

- `src/pages/[lang]/index.astro`：首页结构和区块样式
- `src/components/Header.astro`：全局导航和移动菜单
- `src/components/SearchModal.astro`：搜索弹窗和结果交互
- `src/components/Footer.astro`：页脚分组
- `src/layouts/Article.astro`、`src/components/TableOfContents.astro`、`src/components/ArticleShare.astro`：文章阅读辅助体验

不修改内容 schema、路由结构、部署配置、广告配置和历史内容。

## 数据流

首页继续从 Astro content collections 和本地数据源读取内容。搜索继续请求当前语言路径下的 `/search-index.json`。导航和页脚继续使用现有 i18n 常量与 `getRelativeLocaleUrl` 生成链接。

新增内容类型标签时，优先在搜索结果渲染阶段根据 URL 或索引字段推断；如果现有索引已经包含类型字段，则直接使用。不要为了搜索 UI 改动大范围重写内容索引。

## 错误处理

- 搜索索引加载失败：显示“搜索暂不可用，请稍后再试”类提示，不静默空白。
- 搜索无结果：展示无结果文案和可选常用入口。
- 移动导航打开时：锁定页面滚动，关闭后恢复。
- 外链：继续使用 `target="_blank"` 和 `rel="noopener noreferrer"`。

## 验证计划

至少执行：

- `npm run build`
- 手动检查中文和英文首页
- 手动检查移动宽度下 Header、搜索、页脚
- 手动检查一篇长文章的目录、代码复制、分享区

如改动影响导航或搜索键盘行为，补充 Playwright 或现有 E2E 覆盖。

## 非目标

- 不改域名、部署、Cloudflare、GitHub Actions
- 不改内容目录和 URL 结构
- 不引入新的 UI 框架
- 不做暗色模式
- 不重写全站设计系统

## 成功标准

- 首页首屏能更快说明站点价值和主要入口
- 移动端用户能在两步内进入主要内容区
- 搜索结果更容易判断内容类型，并支持键盘选择
- 页脚扫读成本下降，链接仍完整
- 中文和英文路径保持一致，没有明显布局溢出
