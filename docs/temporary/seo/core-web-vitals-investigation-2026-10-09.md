## 2026-10-10 补查

复核时主分支已更新至 `f7001ba72d836a5033902650c0657603e9128ec4`；新增提交只涉及其他文章的标题和发布日期，本轮修复与其没有冲突。

### 筛选交互

使用仓库的 Playwright Chromium，在 390×844、中英文、4 倍与 8 倍 CPU 限速下，分别测试字体已加载和字体待加载时的原生 `summary` 点击。每个场景展开/收起 20 次，8 个场景重复两轮，共 320 次；同时确认每次 `details.open` 状态确实变化。

两轮 Event Timing 分别记录到 148 条和 144 条目标点击，最长分别为 48ms 和 40ms；事件处理最长约 2.9ms。采集阈值设为 16ms，没有记录的点击不能当作耗时为零。字体待加载场景在前两次点击后释放字体响应；这没有模拟全部第三方脚本、真实网络及设备负载。

这批实验仍未复现报告的 448ms，不能据此判定历史样本错误或宣称线上 INP 已改善。需要该异常样本的真实设备、浏览器及性能轨迹，才能继续确认输入等待、事件处理或绘制等待中的具体原因。分段方法参考 [web.dev 的 INP 优化说明](https://web.dev/articles/optimize-inp)。

### 字体与语言提示栏

从站点实际使用的 Google Fonts 样式取得 Noto Sans 和图标字体，捕获 9 个字体文件，受控返回浏览器实际请求的文件，并等待 `document.fonts.ready`。分别只延迟正文字体或只延迟图标字体，覆盖中英文、390px/1280px、首页/QA Skills 共 16 个场景；其他字体保持正常到达。

| 延迟对象 | 观测结果 | 判断 |
| --- | --- | --- |
| 图标字体 | 语言提示文字的横纵坐标、主内容顶部位置均保持不变。 | 与首轮结论一致，当前图标占位有效。 |
| 正文字体 | 语言提示文字纵向移动 2px；英文横向移动约 1.92px，中文约 0.03px；主内容顶部不变。 | 确认字体切换可带来轻微文字位移，没有复现提示栏突然增加 44px 高度。 |
| 正文字体对其他内容的影响 | 英文 QA Skills 手机场景的字体释放后偏移得分约 0.04612，主要涉及工具栏和介绍区；其他测试场景更小。 | 这是受控窗口的测量，不能作为全站或真实用户 CLS。 |

正文字体变化与图标字体变化需要分开判断；[web.dev 的 CLS 说明](https://web.dev/articles/optimize-cls)也把 Web 字体列为可能原因，并指出被移动元素不一定是根因。本次轻微文字位移不足以解释报告里的 0.151 样本，未据此修改全站字体或语言提示逻辑。

补查的原始记录保存在本机 `/tmp/site-cwv-followup/`，不作为长期留存或提交内容；上述结论保留在本文。临时诊断测试在采样结束后删除。
